How PakuPaku works

PakuPaku is a browser-based messaging experiment: write a note, choose a passkey, and share a link. Open that link with the same passkey to recover your words. Try a different passkey and the link unfolds into a different reading.

Share a message without an account

Write a supported sentence such as “hello. i love you.” The editor checks the vocabulary and grammar, highlighting anything it cannot encode. Choose a passkey and generate a link, then copy that link into the messaging service you already use. The recipient opens it in a browser and enters the passkey.

The app uses one message box for writing and reading. Editing a received message starts a new draft. Your original passkey restores the canonical message: text is lowercased and spacing is normalized.

Why do different passkeys produce different messages?

The passkey influences both the words and the sentence constructions selected by the codec. Each choice feeds into later choices, so changing a key can change the structure of the whole reading. The decoder does not label a passkey as correct or incorrect. Even an empty passkey produces a reading.

The engine uses SHA-256 and HMAC-SHA-256 in its keyed mapping. The parser, dictionary, and codec share a version so the same link and key continue to use the same rules. A link for an unsupported version shows a version error.

Where does the message go?

Encoding and decoding run locally in your browser. The encoded message is carried in the part of the URL after the # symbol, called the fragment; that fragment is not included in the HTTP request to the static hosting server. The app has no message database or account system. Anyone you share the complete link with receives its encoded payload.

Is PakuPaku encrypted messaging?

PakuPaku explores an experimental approach to passkey-based message encoding using cryptographic primitives. Its distinguishing feature is that alternative keys produce alternative language. The project has not established the security guarantees of an independently audited encrypted messenger. Plausible alternative readings alone do not prove that a message cannot be recovered or a likely key guessed.

Use it to experiment with messages, language, and cryptography. An empty or easily guessed passkey offers no meaningful secret for a recipient to keep. For the implementation and current limitations, see the codec documentation and tests on GitHub.

Where can I find PakuPaku on GitHub?

The project lives at github.com/bbkianmajd/pakupaku. The live app is bbkianmajd.github.io/pakupaku/. The repository includes the browser interface, dictionary, parser, codec, tests, and design notes. Issues and implementation feedback are welcome in the issue tracker.
